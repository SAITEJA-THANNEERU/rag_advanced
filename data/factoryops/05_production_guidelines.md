# FactoryOps — Production Guidelines

## 1. Purpose

This document describes the Production Management module in FactoryOps.

The module tracks production activities across factory machines, production lines, shifts, and products.

It supports:

- Production shift logging
- Planned versus actual production tracking
- Defect and scrap monitoring
- Downtime tracking
- Cycle-time monitoring
- OEE reporting
- Production achievement and shortfall analysis
- Machine-wise production analysis

The RAG assistant should use this document to explain production workflows and KPI definitions. Current production figures must be retrieved from operational database records.

## 9. Production Achievement

Production Achievement measures actual output against planned output.

**Formula:**

`Production Achievement (%) = (SUM(actual_units) / SUM(planned_units)) × 100`

Interpretation:

- 100% means actual production matches planned production.
- Above 100% means actual production exceeds planned production.
- Below 100% means actual production is below planned production.

The application uses this calculation in the Production Planner and Super Admin dashboards.

If planned production is zero, the assistant must handle the division safely and must not report an invalid percentage.

---

## 10. Production Shortfall

Production Shortfall measures the difference between planned and actual production.

**Formula:**

`Production Shortfall = SUM(planned_units) - SUM(actual_units)`

Interpretation:

- Positive value: production is below plan.
- Zero: production matches plan.
- Negative value: production exceeds plan.

A negative shortfall represents surplus production, not a production failure.

---

## 11. Defect Rate

Machine-wise Defect Rate measures the proportion of defective units against actual production.

**Formula used in the Admin Dashboard:**

`Defect Rate (%) = (SUM(defect_units) / SUM(actual_units)) × 100`

The backend plant KPI calculation also uses:

`Defect Rate (%) = (SUM(defective_units) / SUM(actual_units)) × 100`

### Important distinction

The application uses `defect_units` in one calculation and `defective_units` in another.

These fields must not be assumed to be interchangeable without checking their actual data mapping and meaning.

The RAG assistant should identify which field and calculation it used when reporting defect rate.

---

## 12. Yield Rate / First-Pass Yield

The Quality page uses the following calculation:

`Yield Rate (%) = ((actual_units - defective_units) / actual_units) × 100`

This represents the proportion of actual production that is not recorded as defective.

The application also displays an Inspection Pass Rate value of 99.4% as a hardcoded figure.

**Important:** The 99.4% Inspection Pass Rate is not a dynamically calculated live metric in the inspected implementation.

The assistant must not present it as a verified live inspection result.

## 13. Overall Equipment Effectiveness (OEE)

OEE stands for Overall Equipment Effectiveness.

It is represented through three components:

- Availability
- Performance
- Quality

The supplied production records contain:

- `availability_percent`
- `performance_percent`
- `quality_percent`
- `oee_percent`

However, the application contains multiple OEE calculation paths.

### Dashboard Overall OEE

The Admin and Manager dashboards calculate overall OEE using:

`Overall OEE = SUM(oee_percent) / COUNT(production_records)`

These dashboards include records with zero OEE values.

The Super Admin dashboard averages only records where:

`oee_percent > 0`

This creates a potential difference between dashboard values.

### Backend Plant OEE

The backend KPI calculation uses the average machine OEE for machines that are not offline or under maintenance.

If no suitable machine values are available, it uses a fallback value of 85.0.

This calculation uses machine-level OEE values rather than directly averaging `production_records.oee_percent`.

### Important limitation

There is no fully reconciled, stakeholder-approved canonical OEE calculation across all dashboards and backend KPI logic.

The RAG assistant must identify the source and calculation used when presenting OEE.

It must not silently combine these different calculation methods.

## 14. Availability, Performance, and Quality KPI Calculations

The backend currently calculates certain plant KPIs using heuristic formulas.

### Availability

The backend uses:

`Availability = clamp(100 - (maintMachines × 4.5) - (warnMachines × 1.5), 75, 98.5)`

Where:

- `maintMachines` represents the number of machines under maintenance.
- `warnMachines` represents the number of warning machines.
- `clamp` restricts the result to the specified minimum and maximum.

This is a heuristic calculation, not a direct calculation from shift downtime.

### Quality

The backend first calculates defect rate:

`Defect Rate = (SUM(defective_units) / SUM(actual_units)) × 100`

Then calculates:

`Quality = clamp(100 - Defect Rate, 90, 99.8)`

The calculated quality has a minimum floor of 90%.

### Performance

The backend calculates:

`Performance = clamp(avgOee / (Availability × Quality / 10000), 80, 99.0)`

This is a back-calculated value based on average OEE, availability, and quality.

### RAG instruction

Do not describe these backend heuristic calculations as direct sensor-derived production measurements.

When answering KPI questions, identify whether the value comes from:

- Production records.
- Machine-level values.
- Backend heuristic calculations.
- Dashboard-specific aggregation.

## 15. OEE Target Variance

The Manager dashboard also calculates population variance for OEE target analysis.

This is a statistical variance measure.

The assistant should not confuse OEE variance with production shortfall or defect rate.

If a user requests the exact OEE variance calculation, retrieve and verify the corresponding implementation before explaining the formula.

## 17. Production Data Quality and Limitations

The supplied cleaned production dataset contains:

| Attribute | Observed Value |
|---|---|
| Total records | 6,480 |
| Date range | 2026-07-01 to 2026-09-28 |
| Machines | 24 |
| Shifts | 3 |
| Products | 6 |
| OEE range | 0–98.26% |
| Performance range | Up to 102.8% |

### Known limitations

1. The dataset represents a simulated 90-day operational period.
2. Some production fields used by the application are absent from the inspected SQL CREATE TABLE definition.
3. Different dashboard components use different OEE aggregation rules.
4. Backend availability and performance are calculated using heuristic formulas.
5. The Quality page contains a hardcoded Inspection Pass Rate of 99.4%.
6. The Production Planner machine tooltip displays a raw OEE sum instead of an average in one location. The schedule table calculates the average correctly.

The assistant should not present these implementation-specific figures as a single authoritative KPI standard.

## 20. Accuracy Rules

The RAG assistant must follow these rules:

1. Never invent production records or quantities.
2. Use live database records for current production statistics.
3. Clearly distinguish planned units from actual units.
4. Distinguish `defect_units` from `defective_units`.
5. Do not assume all OEE calculation paths produce identical results.
6. Identify the source and calculation method when reporting OEE.
7. Do not describe heuristic availability and performance as direct sensor measurements.
8. Do not present hardcoded dashboard figures as live analytics.
9. Treat negative production shortfall as surplus production.
10. Handle zero denominators safely.
11. Verify actual database columns before querying schema-drift fields.
12. Distinguish simulated dataset statistics from current operational values.
13. Do not invent approved defect targets, quality limits, or production standards.

## 22. Summary

FactoryOps Production Management tracks production quantities, shifts, products, machine performance, defects, scrap, downtime, and production KPIs.

The RAG assistant should use this document for production concepts and calculation explanations.
